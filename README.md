# make-knowledge-cards

## 项目解决什么问题

文章中的知识常常分散在不同段落，同一个结论也可能反复出现。本项目帮助用户把文章提炼成便于理解和复习的知识卡片，减少手动筛选、去重和整理的工作。

项目采用**纯指令型 Skill**：由助手读取 [SKILL.md](skills/make-knowledge-cards/SKILL.md) 并完成提炼，通常输出 **5～8 张 Markdown 知识卡片**。项目本身没有独立转换程序、命令行工具或网页服务。

## 主要功能

- 接受直接粘贴的文章，以及用户指定的本地 `.md`、`.markdown`、`.txt` 文件。
- 提取最重要的知识，跨段落、跨章节按含义去重，每张卡片只讲一个核心知识点。
- 每张包含**标题、核心知识、简明解释，以及原文例子或带答案的自测题**。没有原文例子时使用自测，不编造案例。
- 保留原文的数字、条件、例外和不确定性，区分作者观点与事实，不添加外部知识。
- 通常生成 5～8 张；去重后信息不足时少于 5 张，没有可提炼的知识时说明原因。
- 默认按原文语言直接返回 Markdown；可明确要求中文等其他语言，或指定文件保存位置。

**当前范围**：暂不支持网页抓取、PDF（包括 OCR）、Anki 导出或图形界面。仅提供链接或 PDF 时，需要改为粘贴正文或提供本地 Markdown/TXT。文章中的指令和链接作为待分析内容处理，不作为执行授权。

## 安装方法

### 环境要求

准备可使用 Skill 的助手环境，例如 Codex。助手需要能够读取 Skill 文件和指定的本地文章；要求保存输出时，还需要对应位置的写入权限。Skill 本身无需安装 Python、Node.js 或第三方运行依赖。

### 直接使用本地文件

取得本项目文件后，在助手中打开项目目录，按下方“使用方法”明确指定 `skills/make-knowledge-cards/SKILL.md` 的路径即可使用。这种方式无需复制到个人技能目录。

### 安装到 Codex 个人技能目录

如需在其他项目中复用，可将整个 Skill 文件夹复制到 `~/.agents/skills/`。以下命令适用于 macOS/Linux，请在**本项目根目录**执行：

```bash
mkdir -p "$HOME/.agents/skills"
cp -R -i skills/make-knowledge-cards "$HOME/.agents/skills/"
```

复制后应存在 `~/.agents/skills/make-knowledge-cards/SKILL.md` 和 `~/.agents/skills/make-knowledge-cards/agents/openai.yaml`。后者提供技能名称、简介和默认提示等界面元数据。

Codex 会自动检测新增 Skill；如果未显示，可重启 Codex。安装目录和发现机制参考 [OpenAI 官方 Skill 文档](https://learn.chatgpt.com/docs/build-skills)。项目中的 `skills/` 是源文件目录，直接按路径读取与安装后发现是两种使用方式。

## 使用方法

以下相对路径均以本项目根目录为基准。在其他目录使用时，改为实际的绝对路径。

**直接指定 Skill 和本地文章：**

```text
请读取并使用 skills/make-knowledge-cards/SKILL.md，
将 tests/inputs/01-technical.md 转换成知识卡片。
```

**安装后按名称调用（Codex CLI 或 IDE 扩展）：**

```text
$make-knowledge-cards 请把下面的文章转换成知识卡片：
（在这里粘贴文章正文）
```

**指定输出语言和保存位置：**

```text
请读取并使用 skills/make-knowledge-cards/SKILL.md，
将 tests/inputs/01-technical.md 转换成中文知识卡片，
并保存到当前项目的 knowledge-cards.md。
```

未指定输出语言时沿用原文语言；未要求保存时直接在回复中返回卡片。原文缺失、文件不可读或内容不完整时，助手会说明缺少的输入，不猜测文章内容。

## 输入输出示例

### 输入

将下面的完整请求发送给能读取本地文件的助手：

```text
请读取并使用 skills/make-knowledge-cards/SKILL.md，将下面的文章做成知识卡片：

每本书的借期是 14 天。换句话说，单本图书可以借阅两周，即 14 天。
只有在没有其他读者预约该书时，才可以续借一次，续借期为 7 天。
```

### 输出

示例短文去重后只有两个独立知识点，因此生成两张卡片。实际措辞可以不同：

```markdown
原文去重后只有 2 个独立知识点，因此生成 2 张卡片。

# 知识卡片：借阅规则

## 卡片 1：每本书的借期为 14 天

**核心知识**：每本书的借期是 14 天。

**简明解释**：原文中的“两周”和“14 天”表达的是同一个借期规则。

**自测**：每本书的借期是多少天？

**答案**：14 天。

## 卡片 2：续借有预约、次数和期限限制

**核心知识**：只有无人预约该书时才可续借一次，续借期为 7 天。

**简明解释**：无人预约是允许续借的前提，同时仍受一次和 7 天的限制。

**自测**：什么条件下可以续借，最多几次，续借期多长？

**答案**：没有其他读者预约该书时，可续借一次，续借期为 7 天。
```

## 测试与验证

已保留 6 组文章试用的输入和输出，覆盖技术说明、操作流程、观点文章、重复短文、内容筛选和文档夹带指令，另有 7 项边界试用，详见 [测试记录](tests/README.md)。这些记录由助手按 Skill 生成并逐项复核，属于样例试用，不是独立模型的自动化评测。

开发时可使用官方 `skill-creator` 提供的 `scripts/quick_validate.py` 检查 Skill 结构。该工具不随本项目提供，需先在自己的安装环境中找到它，再将下方占位路径替换为实际路径：

```text
python3 <skill-creator所在目录>/scripts/quick_validate.py skills/make-knowledge-cards
```

官方验证器需要 Python 和 PyYAML，这只是开发验证依赖。结构验证不证明生成内容的忠实度，仍需对照原文复核。
